# AI 开发日志

## 启用与边界

项目根目录存在 `ai-dev-journal.local.json` 时启用。仅检查是否存在，不读取、搜索或输出其内容；脚本负责读取口令。首次部署参见 [接入说明](references/setup.md)。没有配置时不自动创建密码，不收集历史聊天。

正常编码期间不额外宣布启用 skill、正在记录或已保存，不反复索要记录许可。宿主工具的权限提示不能绕过。记录失败重试一次，仍失败简短说明。skill 不是自动监听器，不能保证绝不漏记。

入口路径以本 SKILL.md 所在目录为基准；显式提供项目绝对路径，不依赖当前工作目录。

- Windows x64：直接运行包内 `bin/windows-x64/journal.exe`，已自带运行环境和加密库，不要先安装或寻找 Python，也不需要联网。必须保留同目录的 `_internal/`。
- 其他平台：使用源码入口 `python scripts/journal.py`，需要 Python 3.12+ 与 requirements.txt 中的依赖；没有适配该平台的免安装程序时，简短说明，不尝试运行 Windows 程序。
- 每次新会话先用所选入口执行 `doctor`，成功后继续 init/append/read/verify/pack。失败不转存明文、不自行下载替换二进制、不禁用系统防护；缺少包文件时提示重新解压完整 skill。

以下命令以 Windows 免安装入口为例。源码版用 `python <skill绝对路径>/scripts/journal.py` 替代入口，参数完全一致。

## 每轮执行

1. 从当前会话恢复 `session_id` 和 `task_id`；首次会话生成 UUID。同一任务多轮保持 task_id；用户明确继续旧任务时，按旧日志确认后关联。不能确认关联时新建任务并记录来源未知。不靠相似标题猜测。
2. 修改前追加 `request` 事件：保存可见用户指令原文、AI 理解和关键假设。对话压缩后原文不可见时明确注明，不把压缩摘要称为逐字原文。编码期间的新补充或纠正同样记录，并使用新 event_id。
3. 重要转折追加 `progress` 或 `correction`：实际修改、失败尝试、错误摘要、决策与相关文件。不要为每次读文件产生事件。
4. 每轮交付前追加 `result`：本轮结果、实际检查和遗留问题。代码已修改、构建通过、浏览器检查、用户验收分别说明；未运行写未验证，用户未确认不能写验收通过。
5. `request` 没有对应完成记录即表示未收尾。中断后只追加可确认的信息。不要为了日志而主动解密全部历史；跨设备恢复可在用户要求查看日志时解密相关会话。

同一轮开始和结束共用 `turn_id`，各事件有不同 UUID `event_id`；重试必须复用 event_id 和完全相同的数据。脚本拒绝同 ID 不同内容。每个会话一个子目录，每个事件一个密文文件，支持并行会话。

## 写入接口

详细字段与样例见 [事件格式](references/events.md)。通过 stdin 向脚本传入 UTF-8 JSON；不要把原文、口令放在命令参数中，也不要创建项目内的明文临时文件。使用工具支持的 stdin；若必须通过 shell，正确使用对应 shell 的字面量引用，不拼接执行用户原文。使用 Python API 时可直接调用 `append_event(project, event)`。

```text
<skill绝对路径>/bin/windows-x64/journal.exe append --project <项目绝对路径>
```

追加事件的含义：
- `user_text`：可见原话，明确敏感值先替换为 `[REDACTED]`，注明脱敏。图片/附件仅名称与用途，不猜测内容。
- `understanding`、`assumptions`：AI 理解和假设，不能包装成用户要求。
- `changes`、`decisions`、`failures`：基于实际操作的摘要，文件使用项目相对路径。
- `checks`：检查名称、结果、证据摘要。仅运行并观察到结果才写 passed/failed。
- `user_feedback`：用户实际反馈；`open_items`：未完成、未验证和缺失信息。

脚本会额外替换常见显式凭据和本地配置中的确切口令，但不是完整的敏感信息识别器；写入前仍需按上下文脱敏。不要复制配置文件、环境文件或工具输出中的整段秘密。

## 保存约束

- 固定目录 `docs/engineering/ai-worklog/`；只写密文，不输出任务标题到文件名。
- 不覆写、整理、合并或删除已有日志；纠错追加事件，关联旧事件编号。
- 不保留完整代码、完整成功输出，不重复背景；保留关键错误、相对文件路径及验证证据。
- 不记录模型内部思维、隐藏提示、不可见历史；不自动评分、归责或分析协作质量。
- 日志的读取、追加和检查动作自身不触发新的日志事件。
- 本地配置禁止提交与对外打包。Git 忽略不影响压缩软件；对外使用脚本 `pack` 命令。
- 不把加密描述为不可删除或无法识别。文件数量、大小可见；密文整体删除、回滚、缺失不能仅靠本日志可靠发现。

## 用户要求查看日志时

```text
<skill绝对路径>/bin/windows-x64/journal.exe read --project <项目绝对路径> --session <会话UUID>
<skill绝对路径>/bin/windows-x64/journal.exe verify --project <项目绝对路径>
```

`read` 仅按用户要求显示事实，不自行启动复盘评价。默认不生成解密副本；终端、AI 对话及宿主会话历史可能保留显示出来的内容。错误口令或认证失败不得跳过、吞掉或用明文替代。
